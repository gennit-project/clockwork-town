# Epic 2 — Authoring substrate

**Read [README.md](README.md) first** for orientation. This epic gives the player the
tools to build and customize the world's content: a real item catalog, deeper
character authoring (family trees, relationships, memories), and world/region config.
It is the prerequisite for hand-building the default town and the tutorial (Epic 5).

## Goal

Make every piece of content the simulation consumes authorable from the UI — items
from a reusable catalog, characters' full social/biographical data, and the world's
time/climate settings.

## What this epic unlocks

- The default-town and tutorial content work in Epic 5 (you can't hand-author 10
  dramatic households without family-tree/relationship/memory editing).
- The disapproval data that Epic 1.3 needs.

## Prerequisites

- **Epic 0.2/0.3** (traits/values) — the character editor expansion here adds
  traits/values/family/relationships/memories on top of those systems.

## Current state to build on

- **Item authoring exists inline per-room** in `frontend/src/views/SpaceDetail.vue`
  (name, description, max users, comfort, item roles, affordances). Backend:
  `createItem` / `createManyItems` / `updateItem` with `ItemInput` / `UpdateItemInput`
  / `ItemAffordanceInput` (`src/resolvers/world.ts`, `src/schema.graphql`).
- **There is NO item catalog page** — `/library/items` is a "Coming Soon"
  `LibraryStub.vue`. But the pattern to copy is already built and working for **lot
  templates** (`LotTemplates.vue`, `LotTemplateDetail.vue`, `LotTemplateEdit.vue`)
  and **household templates** (`HouseholdTemplates.vue`, `HouseholdTemplateDetail.vue`).
- **Character editor is partial** (`CharacterEditor.vue`: name/age/bio/schedule only).
  No traits/values/family/relationships/memory editing.
- **World/region config is absent** — `/settings` is a stub; `Region.kind` exists.

## Work items (in order)

### 2.1 — Item catalog + place-from-catalog `[M]` — this is the old "Phase 7"

**Status:** Not started (catalog absent; inline per-room authoring exists).

**What to build.** Mirror the existing lot/household template-library pattern for items:
1. **Item catalog page** at `/library/items` (replace `LibraryStub.vue`): browse,
   create, and edit item templates. Each template carries the planner metadata:
   - food source / storage / prep semantics,
   - seating semantics,
   - human vs. animal usability,
   - affordances + weights, and max simultaneous users,
   - any public/private / access-related fields.
2. **Place from catalog:** on a room/space detail page (`SpaceDetail.vue`), add an
   item *from the catalog* (not only the current manual inline form).
3. **Edit after placement:** the same form lets you customize an item after it's in a
   room.
4. **Template linkage:** when editing an item created from a template, ask whether
   changes apply to *this item only* or *all items linked to the same template*.
5. **Save as template:** any authored item can be saved back into the catalog.
6. (Future-friendly) item can be added to a character's inventory.

**Reference implementation.** Copy structure from `LotTemplateEdit.vue` /
`LotTemplates.vue`. Reuse the existing item mutations; add template
storage/linkage following the lot-template precedent.

**Done when.** A user can create an item template in the catalog, place it into a
room, customize the placed instance, and choose template-vs-instance scope on edit.

### 2.2 — Character authoring: traits, values, family, relationships, memories `[M]`

**Status:** Partial. `CharacterEditor.vue` edits name/age/bio/schedule. Traits/values
editing arrives with Epic 0.2/0.3; this item adds **family trees, relationships, and
memories**, plus the disapproval data Epic 1.3 needs.

**What to build.**
1. **Family tree editing** — define parent/child/sibling/spouse links between
   characters. (The relationship model is directed with labels; family links should
   reuse it.)
2. **Relationship editing** — set/seed relationships with existing characters
   (label + starting scores) at create or edit time.
3. **Memory editing** — view and edit a character's memories (memories are also auto-
   generated by the sim; this is manual authoring/seeding).
4. **Disapproval/approval authoring** — what this character approves/disapproves of
   (feeds Epic 1.3).
5. **Relationship-type filters** — in the relationship list, filter by relation type
   (mother-daughter, mother-son, father-son/daughter, sibling pairs, friend-friend,
   partner-partner). (Today only `eventType` memory filtering exists.)

**Where it plugs in.** Extend `CharacterEditor.vue` and the relationship views
(`CharacterRelationshipsTab.vue`). Backend relationship mutations already exist
(`persistCharacterRelationship`); family links may need a thin schema addition if not
already expressible via labels.

**Caution.** Deleting characters must not orphan relationships/memories into corrupt
graph state. Kùzu 0.6 has known relationship-delete quirks (see the project memory on
Kùzu rel-index corruption). Handle deletes carefully and test the delete path.

**Done when.** A character's family tree, relationships, memories, and
approvals/disapprovals are all authorable and persist; the relationship list filters
by relation type; deleting a character cleans up cleanly.

### 2.3 — World / region configuration `[S–M]`

**Status:** Absent. `/settings` is a stub; `Region.kind` exists.

**What to build.**
- Set the **world's starting date and year**.
- Set the **region's climate**: temperature + precipitation that repeat year-round;
  optional **preset climates**. The region surface shows current temperature and
  whether it's raining/sunny (text only).

**Where it plugs in.** New settings UI (replace the relevant `ServiceDeskStub.vue`
under `/settings`). Calendar/time already exists in `utils/simulationCalendar.ts` —
wire the start date/year into world creation. Weather is presentation + a simple
state value initially; sim effects of weather (e.g. indoor preference when raining)
can come later.

**Done when.** A new world can be created with a chosen start date/year; a region
shows a configurable, repeating climate with current temperature + sky state.

## Out of scope for this epic

- Visual/spatial map placement of lots and roads (parked — see
  [parked-long-term.md](parked-long-term.md)). Lot creation remains list-based as it
  is today; Epic 5's build-and-staff flow uses that.
- NPC generation and job slots (Epic 4).
- Images (item/room pictures are cut).
